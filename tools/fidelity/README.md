# Fidelity tools

Measure how closely Qraw renders diagrams compared with draw.io itself. Results and
the difference classes are in [docs/FIDELITY.md](../../docs/FIDELITY.md). Nothing here
ships: the draw.io binary and the reference renders are downloaded or generated into a
directory outside the repository and can be regenerated by script at any time.

| File | Purpose |
|---|---|
| `fetch_drawio.sh <dir> [tag]` | Downloads the official draw.io Desktop Linux AppImage from the GitHub releases of `jgraph/drawio-desktop`, verifies its checksums and extracts it (no FUSE needed) into `<dir>/app/`. |
| `run_fidelity.sh <drawio-dir> <out-dir>` | Exports `sample.tsv` with draw.io and Qraw, scores every pair, writes `summary.md`, `results.csv`, `classes.md` and `composites/` into `<out-dir>`. Idempotent: draw.io PNGs already in `<out-dir>/drawio/` are reused. |
| `sample.tsv` | The sample: file, family, feature. 113 corpus files and 10 feature probes. No private files. |
| `probes/` | Ten small diagrams that isolate one feature each (fills, shapes, labels, edge styles, markers, jumps, containers, sketch); `generate_probes.py` writes them. |
| `diff/` | `qraw-fidelity-diff` (Qt, built with `-DQRAW_BUILD_TOOLS=ON`, never installed) and its self-test `tst_tools_fidelity_score`. |
| `classify.py <out-dir>` | Counts, per difference class, the sample files that use the feature and how far they are from draw.io (`classes.md`). |
| `make_crops.sh <out-dir>` / `crops.tsv` | Regenerates the example crops in `docs/fidelity/`. |

## Run it

```sh
tools/fidelity/fetch_drawio.sh /some/dir/outside/the/repo/drawio     # about 100 MB download, 350 MB extracted
tools/fidelity/run_fidelity.sh /some/dir/outside/the/repo/drawio build/fidelity
tools/fidelity/make_crops.sh build/fidelity                          # only when refreshing docs/fidelity
```

`run_fidelity.sh` configures the `release` preset with `-DQRAW_BUILD_TOOLS=ON`, builds
`qraw-cli` and the diff tool, and takes about 3 minutes on the first run (draw.io needs
about 1.3 s per file) and 10 s afterwards. Environment: `QRAW_FIDELITY_BORDER` (10),
`QRAW_FIDELITY_SCALE` (1), `QRAW_FIDELITY_JOBS` (4).

- SHA-512 (base64) `h2TVa53rkat5JXTbii9Kfuur7ekdkDZIojjlgwljdMAnh0WX0qwIONb4Xb5yBerd+vrzpwMFDeNes07ajq11rQ==`, equal to the value in the release's `latest-linux.yml`.

`fetch_drawio.sh` verifies both and fails on a mismatch, and writes `DIGESTS.txt` next to the
extracted app. Without a tag it takes the latest release; pass a tag to pin one.

## How draw.io is run

Headless Electron works, so no compositor and no browser fallback are needed:

```sh
env -u DISPLAY -u WAYLAND_DISPLAY drawio --ozone-platform=headless --disable-gpu \
    -x -f png -s 1 -b 10 --timeout 120 -o <out>/drawio <out>/inputs
```

One Electron start exports the whole folder. `--no-sandbox` is not needed (the
user-namespace sandbox works), so it is not used. The desktop session is untouched: both display
variables are unset and Electron's headless Ozone backend creates no window. The PNG is opaque
white (no `-t`). Page numbers are 1-based since draw.io 27.0.2 and an image export without
`--page-index` takes the first page, which is what the sample compares.
Other ways (a private `kwin_wayland --virtual`, the web app in headless Chrome) were not needed
and are not implemented.

Qraw side: `qraw-cli --export <file> --output <png> --scale 1 --border 10` from the
release build (page 1, opaque white). Both programs resolve fonts through the same fontconfig;
`run_fidelity.sh` records what it resolves in `<out>/fonts.txt`.

## How a pair is scored

See the comment in `diff/fidelity_score.h`: content boxes, size mismatch kept separate,
top-left or centred alignment plus a nudge of up to one pixel, CIE76 deltaE per 2x2 block for
the pixel score and per 8x8 block for the layout score. The self-test runs synthetic images
(identical, shifted, a missing shape, jitter, blank, size mismatch) through the same code.
