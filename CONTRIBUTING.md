# Contributing to Qraw

Thanks for looking. Bug reports, fixes and new features are welcome. For anything larger than a fix, open an issue first so that the design can be discussed ([DECISIONS.md](DECISIONS.md) records the decisions taken so far, and [ROADMAP.md](ROADMAP.md) lists what is wanted).

## Build and test

[BUILDING.md](BUILDING.md) has the dependencies per platform and all options. In short:

```sh
cmake --preset dev            # Debug, warnings are errors, build/dev
cmake --build --preset dev -j6
ctest --preset dev -j4        # about 50 s on a 24-core machine
```

The test presets run the GUI tests on Qt's `offscreen` platform, so no display is needed. Use `-j4` to `-j6` for the build if memory is tight (each compile job of a Qt-heavy file takes about 0.5 GB). Before sending a change, run the whole suite in `dev`; for changes that touch memory handling, parsing or threads also run `ctest --preset asan` (AddressSanitizer and UBSan, GCC or Clang).

A change is done when it builds without warnings, the whole suite passes, and it comes with a test: a unit test next to the code, or for the file format a case in the corpus (`tests/corpus/`, regenerated by `tools/corpus/generate_corpus.py`). UI behaviour is tested by driving `MainWindow` or `CanvasView` with synthetic input (see `tests/ui/support/`). Rendering changes that alter exported SVG need their golden files updated on purpose (`QRAW_UPDATE_GOLDENS=1`) and the diff reviewed.

## Code layout

| Directory | Contents | May depend on |
|---|---|---|
| `src/core` | The lossless document model (`Document`, `Page`, `Cell`, `Style`, `XmlNode`, ...) | C++20 standard library only, no Qt |
| `src/commands` | Undoable operations, the undo stack, layouts and importers | `core`; standard library only, no Qt |
| `src/format` | `.drawio` codec, compression, embedding in PNG, SVG and PDF, libraries | `core`, QtCore, zlib |
| `src/render` | Style resolution, shape painters, stencils, edge routing, text, export, the canvas tile pipeline | `core`, `format`, QtGui, QtSvg |
| `src/ui` | The editor: window, canvas, tools, docks, dialogs, palette | everything above, QtWidgets |
| `src/diag` | Logging, crash reports, session markers | QtCore |
| `src/cli`, `src/app` | `qraw-cli` and `qraw` | |
| `tests/<module>` | Qt Test executables, registered automatically as `tst_<module>_<name>` | |
| `tools/` | Developer tools (corpus, palette and stencil generators, the fidelity diff, CI helpers, icons) | |
| `packaging/` | RPM, DEB and Flatpak builds | |

Public headers are in `src/<module>/include/qraw/<module>/`, code is in the namespace `qraw::<module>`, and the build refuses a `core` or `commands` that links Qt. [ARCHITECTURE.md](ARCHITECTURE.md) describes the modules and the canvas pipeline in detail, and [docs/design/](docs/design/) the design of each layer.

## Rules that matter

- **All model mutations go through `src/commands`.** The UI, the importers and the CLI never change a `core` object directly. A change is a `commands::Command` (or an operation in `ops_*.h` composed of the primitives) applied inside a `commands::Transaction` through `Editor::edit` or `DocumentSession::edit`. That is what makes undo and redo exact, and it is how the canvas learns what to redraw (the `ChangeSet`). Every new operation is checked to undo and redo to byte-identical output.
- **The round trip is lossless.** Anything the program does not understand (unknown elements, attributes, style keys, comments, processing instructions, namespaces, extensions) must survive a load and save, in its original place and order. Model elements keep their raw ordered attributes; typed accessors parse on demand; setters edit in place. An untouched file must save back to semantically equal XML, and saving twice must give the same bytes. The corpus tests enforce this ([ARCHITECTURE.md](ARCHITECTURE.md), "Lossless model rules"). Do not add a code path that drops or reorders what it does not know.
- **Painting never throws and never fails.** Bad numbers paint nothing for that element, unknown shapes use the fallback painter, and problems go into diagnostics.
- **Follow draw.io's behaviour, and say where you got it.** Where a function follows a draw.io function, cite it in a header comment (`$DRAWIO_SRC/src/main/webapp/js/...`, where `$DRAWIO_SRC` is a local clone of the [draw.io repository](https://github.com/jgraph/drawio), Apache-2.0) and say whether it is a port. Code that is a port of Apache-2.0 code carries `Port of <upstream path> (draw.io, Apache-2.0), modified.` ([THIRD_PARTY.md](THIRD_PARTY.md)). Do not copy code from other projects or from sources with an incompatible licence.
- **No network, no JavaScript.** The program reads only local files and `data:` URIs.
- **Text goes through `tr()`.** Menu text follows the KDE Human Interface Guidelines; `tst_ui_menu_conventions` and `tst_ui_accessibility` check menus, shortcuts and accessible names, so a new control needs an accessible name.
- **Tests are deterministic.** Use `isolateSettings()` in UI tests so the developer's real settings are untouched, compare pixels in device pixels, and keep time budgets to the work-counter gates where possible.
- **Style.** C++20, `.clang-format` in the repository root, readable and split into small functions named after what they do (or after their draw.io counterparts). Explain why, not what, in comments.

## Generated and vendored data

Do not edit these by hand; regenerate them with the tools and commit the result.

- `resources/stencils/`, `resources/palettes/`, `resources/styles/default.xml` and the templates come from a draw.io checkout (`tools/stencils/`, `tools/palette/`, see the READMEs there). Their licences must stay beside them ([THIRD_PARTY.md](THIRD_PARTY.md)).
- `tests/corpus/` is generated by `tools/corpus/generate_corpus.py`; the files under `upstream-templates/` are byte-exact and must not be reformatted.
- `resources/icons/hicolor/`, `.ico` and `.icns` are generated from the SVGs (`cmake --build --preset dev --target regenerate_icons` with `-DQRAW_BUILD_TOOLS=ON`).
- `src/ui/i18n/qraw_en.ts` is refreshed with `cmake --build --preset dev --target update_translations`.

## Documentation

Update the docs that your change makes untrue: [FEATURES.md](FEATURES.md), [COMPATIBILITY.md](COMPATIBILITY.md) (the matrix has a test reference for each row), [KNOWN_ISSUES.md](KNOWN_ISSUES.md), [CHANGELOG.md](CHANGELOG.md) and, for a design decision with consequences, a new entry in [DECISIONS.md](DECISIONS.md). If something in the build instructions is wrong, fix [BUILDING.md](BUILDING.md).

## Reporting bugs

Include the version (Help > About, or `qraw-cli --version`), the platform, the steps, and if possible a small `.drawio` file that shows it (remove anything private first). For a crash attach the report from the `crashes/` folder of the data folder; it contains no document content ([README.md](README.md#logs-and-crash-reports)).
