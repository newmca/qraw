# Known issues

- **Editor gaps.** Multi-selection handles do not preview group children or layouts live, and leave `transparentBounds` groups with a child layout alone; loop and entity-relation edges keep the plain waypoint and virtual handles (draw.io gives a self-loop segment handles); no page shadow; fit zoom snaps to the 5 % grid; right-to-left scrolling is untested.
- **Containers.** Only `childLayout=stackLayout`, `tableLayout`, `treeLayout`, `circleLayout` and `flowLayout` are executed; `organicLayout` and `rack` are kept in the file and not run. Stack layout ignores `wrap` and `borderCollapse=false`, and resolves `startSize` and `footerSize` from the cell's own style (a custom stylesheet entry for `swimlane` is not seen). A collapsed container without `alternateBounds` shrinks to its title; draw.io uses the label's preferred size. Dropping uses the topmost cell under the pointer, not mxGraph.getSwimlaneAt, and never targets a collapsed container or a table. `contractParents` and `recursiveResize` are not modeled; no keyboard shortcut for fold/unfold.
- **Tables (merged cells and collapsed borders are done).** Not implemented: moving a column or row by dragging, Ctrl and Ctrl+Shift border drags (resize or distribute all rows or columns), Insert Row/Column on a selection of several cells (the table decides), copy/paste of part of a table (a pasted row or cell is not re-laid out as a table part), the striping colours of a table (`evenRowColor`, `oddRowColor`, `evenColumnColor`, `oddColumnColor`) and the glass effect of a collapsed table's title, and the Format panel's Collapsed Borders switch (set `tableRender` in Edit Style; unlike draw.io, changing it does not convert the `top`, `left`, `bottom` and `right` flags of the rows and cells). The table handles are not shown for rotated tables. The layout rewrites every cell's `alternateBounds` and rounds row positions on the first edit that touches a table, as draw.io does; opening and saving never change them. **Merged cells:** as in draw.io no span is adjusted when rows or columns change: inserting a row or column inside a span gives the new cells no span (the span then covers them and the cell that was covered is shown again), and deleting a row or column that holds the covered cells of a span leaves the span to cover whatever follows. Merge Cells refuses a range that contains a merged cell (draw.io does not check the first cell). The border handles of columns and rows belong to the grid, not to the cells: the handle of a column border is drawn across a merged cell that spans it, and dragging it resizes the column in every row and the layout then fits the merged cell over its columns. A cell that is covered has no state, so it cannot be clicked or found by rubber band; select the merged cell and unmerge. **Collapsed tables:** the rows' and cells' own shapes paint nothing when their shape is a rectangle (`tableRow`, `partialRectangle`, `rectangle`, non-rounded `swimlane`); a cell of any other shape paints itself over the table's grid. `strokeColor=inherit`, `fillColor=inherit`, `parentFillColor` and `parentStrokeColor` are resolved for rows and cells of a collapsed table only; for any other shape they mean no colour. A row's or cell's own shadow and glass are not painted in a collapsed table. A table that is itself collapsed (folded) shows only its title, as before.
- **Label editor.** Markup beyond b/i/u/s/sub/sup/a/font/span/lists/div/br is flattened when a label is edited. Autosize on commit measures with the same text layout the raster canvas draws, so the size differs a little from draw.io's DOM measurement; it does not set a swimlane's `startSize`, does not grow a container to hold its children, and a cloned hover-arrow vertex copies the label text but not the cell's other attributes. The editor of a rotated label shows no I-beam cursor over it and moves with the scene (it is a scene item, not a window child).
- **Default styles and fonts.** See COMPATIBILITY.md, "Default styles": the defaults do not follow the last edited style, a Shift drop still applies them, and the Style tab has no Clear Default Style button (it is in the Edit menu and the blank-canvas context menu). The font list shows installed families only; web fonts (`fontSource`) are not offered, and the entries below the recent fonts are drawn in the UI font, not in their own family (loading every family to preview it is slow).
- **Edit actions.** Duplicating a selection whose edges join cells with different parents drops those edges' terminals; Align Center/Middle use the first selected cell's centre (like draw.io); pasting a bundle snaps its top-left corner to the grid.
- **Arrange.** Rotate 90 Degrees reverses a self-loop without waypoints as it is (draw.io first materialises the loop's routing as inner waypoints, so the loop direction does not flip). Its direction style is written whether or not a view state exists (draw.io skips the step without one), and it does not change the connection constraints of an edge end whose target is missing. Autosize does not update group bounds from their children (`updateGroupBounds`, `transparentBounds` padding), does not clear `autosizeText`, and leaves tables and swimlanes alone. Edit Geometry has no Relative or Offset fields: the upstream dialog body is not in the pruned clone. Flip has no shortcut (draw.io has none either). The reverse turn (`turnCells(..., backwards=true)`, draw.io's Shift+turn) has no menu item or key yet.
- **Insert menu.** Insert > Table inserts a plain table (the structure of `Graph.createTable`): draw.io's picker also offers a Title check box (a header row) and a Container check box (a cross-functional swimlane), and Shift, Ctrl or Alt on the click choose those or a free insert point; none of them is implemented (the palette has the titled tables). The picker always shows the whole 20 x 20 grid (draw.io's grows with the pointer, from 5 x 5). Insert Text opens the editor on a text cell that is only inserted when the text is committed (an empty text or Escape inserts nothing), as a double click on blank canvas does; draw.io's insertText inserts it at once. There are no single-key shortcuts for Insert (draw.io binds A and L), and no Insert items for shapes, Layout or the rest of draw.io Desktop's Insert menu . Insert > Image has no web search and no crop; an image at a web address is not downloaded, so its cell is 120 x 120 (resize it, or choose a file). An image copied as a file in a file manager (URLs, no image data) is not pasted as an image; dropping image files on the canvas is not supported. The insert point is the pointer only while it is over the canvas; menu commands (the pointer is on the menu) insert at the viewport centre, as draw.io does, and the centre of the new cell, not its corner, is put on the point. An image pasted from the clipboard is encoded as PNG whatever its source format.
- **Insert > Advanced.** PlantUML is not implemented: draw.io renders it on a server (or with Java and Graphviz), and a local-first native editor ships neither; the item is absent from the menu (ROADMAP.md, deferred). Mermaid is our own reader of a subset (COMPATIBILITY.md): other diagram types (class, state, ER, Gantt, pie, journey, git graph, mindmap, timeline, C4, ...) are refused with an error that names the supported ones; in flowcharts the new `@{ shape: ... }` syntax, edge ids, markdown formatting, icons, `click` and `linkStyle` properties other than colours, widths and dashes are not supported, and a `flag` node is a `step` shape; in sequence diagrams `rect`, `box`, `destroy`, `title` and links are skipped with a warning and messages are straight edges attached at a fixed height (draw.io's `sequenceEdgeStyle` does not exist here), so dragging a lifeline moves the ends of its messages but not their height. Layouts are ours (D-038, D-039), so positions differ from draw.io's (ELK, the mermaid library): a flowchart with subgraphs is laid out one level at a time, and edges that cross a subgraph border get no waypoints. CSV: rows are never matched with cells that are already in the diagram (no update by `identity`, no data sources), `container` and `list` are not supported, `stylePlaceholders=1` is not (placeholders in styles are replaced once), the global placeholders (`%date%`, `%page%`, ...) in a style stay as written, an unclosed quote is an error where draw.io joins the rest of the line into the field, `%id%` in a style is the identity value (the cells get new ids on insertion), and the cell width of a `label` shape does not know the image that is not there (a CSV with `image=` URLs shows no images: nothing is downloaded). From Text has the list and diagram types only (no table, PlantUML or mindmap and balloon tree types). A text above 10,000 shapes is refused; CSV and Mermaid layouts that are quadratic (organic) are replaced above 500 shapes. The warnings after an insertion are shown in a message box, not in the dialog, and the dialog does not remember its text between uses (draw.io's CSV dialog does).
- **Cell data.** Edit Tooltip edits the HTML source in a plain text box (draw.io's MarkupDialog is a WYSIWYG area with a toolbar). Edit Data has no `label` row for layers or `metaEdit=1` cells (labels are edited in place and layers in the Layers panel), does not remove the `label` when a property named `placeholder` is set with Placeholders on (the quirk of EditDataDialog), cannot rename the cell id, has no Export button, and edits the root cell's data only as plain properties (no data sources, style rules). Tags are a text field: there is no tag filter, tag colours or Edit Tags dialog (ROADMAP.md). Link icon: shown for hovered and selected vertices that have a link and are at least three icon widths wide, not for edges, not rotated with the cell, and never drawn in exports; Ctrl+click is the selection toggle and does not open links (use the icon or Open Link); relative paths, `file:` and `javascript:` links are not opened (a message says so), custom-action links (`data:action/json`) are not run. Edit Image has no Crop and no image search or library; a `clipPath` stays as it is. An embedded image is kept once in the style, but the dialog builds one transient copy of its base64 text when it is applied.
- **Layouts.** The tree and radial layouts are our own (D-038), so a file laid out by draw.io's ELK layouts is not reproduced and the results differ. A tree layout follows outgoing edges from the roots only (`invert` exists in the module, not in the menu); a node reachable from two parents sits under the first; the menu has no options dialog (spacings are fixed per entry) and no Balloon Tree, Mindmap or Parallels entries (Organic and Flow: next item). Org Chart is a vertical tree with elbow edges; it does not stack leaf siblings as draw.io's chart library does. Layouts use the vertex geometry, not the label's bounding box, so a label wider than its vertex can overlap a neighbour. A `treeLayout` container resizes by growing only, a `circleLayout` container fits the circle exactly (as Graph.js does); a `circleLayout` container without a swimlane title still leaves a 40 px strip above the circle (Graph.js uses the default `startSize` for any container). Locked vertices stay but still take their slot, so a layout around them can overlap. Edges between cells in different parents are reset like any other but never routed.
- **Layouts.** Flow and organic are our own (D-039): positions differ from draw.io's ELK results. Flow routes edges with `orthogonalEdgeStyle` and explicit waypoints that bend in the gaps between ranks; the bends of several edges in one gap can run on top of each other, the first and last segment of an edge are always straight along the rank axis, and an edge label is not placed or avoided. Parallel edges are spread only in the middle (they leave the same point of the node). The flow layout treats vertices as boxes and does not wrap rows: many unconnected cells make one long row. Locked vertices and their edges are left out of flow and organic, so they can end up overlapped. Organic ignores the current positions (draw.io's starts from them) and has no options dialog. `childLayout=organicLayout` is not executed, `flowLayout` does not read `extractIsolated` or the model-order option (isolated children are always laid out, ties follow node order), and the flow container re-applies `edgeStyle=orthogonalEdgeStyle` to its edges on every edit, overwriting a custom edge style.
- **Dark diagram mode (D-043).** Only colours that come from the style (and the inline colours of HTML labels, the page background) are mapped: the fixed black and white of a few ported painters (UML and flowchart markers), explicit colours inside stencils and images (including `img/lib` SVGs that draw a themed colour) are drawn as stored, so they can clash with the dark page; `Editor.systemColors` (`Canvas`, `CanvasText`) and `var(--...)` colours are not colours here. The scheme is a per-user preference (by default the canvas follows the application theme, D-053) and a per-export option, not part of the file; the dark UI theme with a light diagram, or the reverse, are both possible through View > Diagram Appearance. The label editor keeps a label's stored inline colours while it is open, and the colour pickers show the stored (light) colours. Palette thumbnails, print and print preview are always light.
- **Freehand (D-044).** The stored form is a stencil vertex chosen without a draw.io file to compare with (COMPATIBILITY.md); there is no brush window (size, smoothing, Close Path, pressure), so a stroke takes its width (2 unless the default style says) and colour from the default style, and the smoothing is a fixed 2 screen pixels; the live stroke is the raw pointer path (it is smoothed on release, so the line moves a little when the button is let go); strokes are open and unfilled (the stencil has only a stroke operation; Edit Shape can add a fill); the tool is a view state that is not remembered between runs. X toggles the tool as a window shortcut (draw.io binds it on the canvas only), so it works from other panels too unless a text field has focus.
- **Not implemented (ROADMAP.md).** `.vsdx` import and export, the remaining JavaScript-only shapes ("Rendering gaps" below), PlantUML, the `glass` effect, export as HTML (the JavaScript viewer), collapsible page tabs, moving table rows and columns by dragging and Ctrl border drags, tag filtering.
- **Extras.** Edit Diagram shows the page text in a plain `QPlainTextEdit` without wrapping or highlighting; a long line is laid out whole, so a page with 1 MB image values is slow to scroll to (a page with tens of megabytes of embedded images opens in under a second, but each megabyte-long line on screen adds to every repaint), and the dialog warns above 8 MB. Text that uses an entity declared in the file's DOCTYPE (`&me;`) parses only while unchanged, because the DOCTYPE is not part of the page text. Upstream's "Select..." list (copy, new window, extract text, anonymize) is absent. Units: the arrow-key step, the drag hint and rulers of draw.io are not unit-aware, and the page-setup paper presets stay in pixels (the custom size fields follow the unit). Copy as Image renders on the GUI thread (the export renderer), so a very large page freezes the window while it renders; the result is limited to 16384 pixels a side (the scale drops to fit); pasting the image elsewhere inserts a picture, it does not restore the cells. A synthetic mouse drag of a page tab was only verified offscreen; the drag was not tried on a real desktop. The collapsible page-tab strip is deferred (ROADMAP.md).
- **Find and replace.** A replacement inside HTML labels works only within one text node; a match spanning inline tags is found but not replaced.
- **Palette.** Azure shapes use `img/lib/*.svg` images that are not shipped, so they insert but draw empty (the palette sections say "icons not included"); `labelPerimeter` is ignored. User libraries (`.xml` mxlibrary): their entries are not found by palette search and cannot be favorites or recent shapes (entry ids are positional); the `title` and `tags` attributes of `<mxlibrary>` and an entry's `style` are ignored; there is no drag to reorder entries; Export writes a copy (a library is saved on every change).
- **Desktop integration.** `appstreamcli validate --no-net --pedantic` and `desktop-file-validate` are clean (also on the installed files and in CI). The metainfo screenshots use raw GitHub URLs on `main`, not a tag (Flathub wants a tag or commit), and `flatpak-builder-lint` reported `appid-url-not-reachable` while the repository was private, and still reports, `appstream-missing-screenshots` and `appstream-screenshots-not-mirrored-in-ostree` (nothing to fix in the files; packaging/flatpak/README.md). There is no MIME-type icon of its own (the generic `x-office-drawing` is used) and no translated metainfo. The Flatpak was built and smoke-tested (`qraw-cli --version`, a PNG export, an offscreen `--screenshot`) on one machine only (Fedora 44); the GUI was not run in a Wayland or X11 session inside the sandbox, so the FileChooser portal (from the platform theme plugins' strings), the CUPS socket and the window icon in a task manager are unverified. The Flathub form of the manifest is a commented template until a tag exists. The Windows resource file and the macOS bundle icon and identifier are set in CMake but are built only by CI; no file association is registered on Windows or macOS. A real Wayland/X11 session has not confirmed that the task manager groups the window under the icon (`StartupWMClass` is omitted on purpose).
- **Math typesetting is not planned.** `math=1` is preserved in files and the formula text is rendered as plain text (nothing is deferred here).
- **Linux packages.** RPM, DEB and Flatpak bundle are built and smoke-tested on one development machine (Fedora 44); the `linux-packages` CI job is the only other build. The RPM is tested on Fedora 44, the DEB on Debian 13 and Ubuntu 25.10, 26.04 and 26.10 (all on the offscreen platform; no real desktop session, no Wayland or X11 run, no printing). Ubuntu 24.04 is not supported (Qt 6.4; the DEB refuses to install). The packages are not signed and are built for x86-64 only. The source archive is `git archive HEAD`, so uncommitted application changes are not packaged (the Flatpak builds the working tree). There is no AppImage, by choice. The package builds run the whole suite with no exclusions. The RPM is built with Fedora's default LTO. The label line pitch on macOS (fonts with a leading) and Return in the Cells panel have only been exercised by CI. The Windows packaging (`qt_generate_deploy_app_script` without plugin arguments before Qt 6.10) has had little testing on Windows. Qt's raster engine rounds the position of a glyph at a negative device coordinate differently from one at a positive coordinate (up to a quarter pixel of antialiasing, with fonts that position glyphs at fractions of a pixel): a label that straddles the top or left edge of a tile can differ in antialiasing from its other half by that much (not noticed by eye; the tile tests compare against a reference that avoids the quirk).
- **Packages.** The Windows installer, the ZIP and the macOS `.dmg` are built in CI but were written without running Windows or macOS, so CI is their only test (the install step lists missing plugins, `tools/ci/smoke_package.sh` runs the exports from the unpacked, installed and mounted packages). They are unsigned: SmartScreen warns; the `.dmg` has an ad-hoc signature only and is not notarised (right-click, Open). The installer is per machine only (D-048; no per-user install, no `.dio` association, no "Open with" entry for other extensions). The macOS bundle is one architecture (the runner's); no universal binary. The `.dmg` has the default layout (no background picture, no Applications link). No AppImage, by choice. Not tested: a double click in Finder (`QFileOpenEvent` is tested by sending the event), launching from the Start Menu entry, an update over an installed older version.
- **Crash reports and recovery (D-049).** (1) Best effort: a crash that corrupted the heap or the stack of the faulting thread can stop the report half way, and `backtrace()` is not formally async-signal-safe (primed at start, fine in practice). Only the thread that installed the handler (the main thread) has the alternate stack, so a stack overflow on a worker thread dies without a report. (2) Backtraces are module offsets, not function names, for `qraw` itself (no `-rdynamic`); resolve them with `addr2line` against the same build (the report names the commit; the commit is taken when CMake configures, so reconfigure after a new commit if the report must match). musl has no `<execinfo.h>`: the report then says there is no backtrace. (3) **Windows is untested:** the handler (`crash_handler_windows.cpp`) and its minidump are compiled in CI and nothing runs them, because the data folder of Windows cannot be redirected for a test; the call stack is the filter's own stack as module+offset, not symbolised (no PDBs ship), and the `.dmp` is for WinDbg. (4) Under ASan/UBSan builds the sanitizer's handlers win for SIGSEGV and SIGABRT: no report (`tst_app_crash_process` skips itself there). (5) macOS: the same code as Linux, run by CI only; the test skips itself when `HOME` cannot be redirected. A crash on macOS also shows the system's crash dialog. (6) The log file is written by the GUI only, is capped by emptying (the lines of the current run before the cap are lost, the previous run stays in `qraw.log.1`), and is not rotated by date. (7) Recovery opens each extra document in its own window; Quit closes only the window it is used in. A session that ended unexpectedly with nothing to recover is reported once and cannot be told from a deliberate `kill` or a logout that killed the process.
- **Accessibility (D-050).** (1) **[NICE]** The canvas is one accessible object (role Canvas, name "Diagram", description "<page>, N shapes, M selected") without a child interface per cell; a screen reader reaches the cells through the Cells panel, not by walking the canvas. (2) Nothing was run against a real assistive technology: Orca and AT-SPI on a desktop session, VoiceOver and Narrator are untested; the tests use Qt's own accessibility interfaces (`QAccessible::queryAccessibleInterface`, `QTestAccessibility`), which prove names, roles, descriptions and events, not what a screen reader says. (3) Alt+Tab and Alt+Shift+Tab (first child, container) are taken by the window switcher of most desktops and reach Qraw only where the desktop leaves them; the same moves are in the Cells panel. (4) The accessible names are checked on the main window and on the dialogs of the screenshot harness (`--dialog`); the system dialogs (file, colour, print, input) are Qt's or the platform's. Labels of check boxes and radio buttons were not brought to sentence case or reworded for this pass. (5) The Cells panel lists the current page only, shows a collapsed row for every container (children appear when it is opened), and shows no thumbnails or colours; the order is document order, which is also Tab's order.
- **Printing.** The interactive print dialog and print preview are not covered by tests.
- **Screenshots are rendered offscreen** (`docs/screenshots/`); native window decorations are not part of them. Interactive behavior on a real desktop (X11/Wayland, high DPI, input methods) has only been exercised through synthetic events.
- **Rendering gaps.** Not drawn or approximated: AWS4 and Kubernetes composite icons (the icon glyph and the group header are missing), shapes that exist only as draw.io JavaScript and are not ported (fallback painter): the remaining palette and corpus names are `mxgraph.bpmn.{data2,conversation2,swimlane,task}`, `mxgraph.basic.{patternFillRect,polygon,arc}`, `mxgraph.arrows2` (all but arrow and twoWayArrow), `mxgraph.floorplan` (stairs, the other doors and windows; `wallU` is ported), `mxgraph.mockup.*` (forms, misc, markup, navigation, buttons), `smileyFace`, `mermaidUsecaseActor`, and the Shapes.js shapes `or`, `xor`, `delay`, `display`, `sumEllipse`, `storage`, `dataStorage`, `loopLimit`, `tee`; edge-only shapes (`flexArrow`, `link`, `arrow`) are always painted by the connector painter, and ported JS shapes do not carry the connection constraints of their upstream classes (the editor's default points apply); `umlLifeline` with `lifelineMirror=1` draws the foot box but not the copy of the label upstream paints into it; `glass=1`, dark mode, `math=1` (plain text), line jumps on `curved=1` edges (curved edges neither jump nor are jumped over; `curveGeometry` is ignored), libavoid and isometric routing, callout/lifeline/cloud perimeters (rectangle), `roundedPerimeter`. Images from `img/lib/**` are not vendored and remote images are never fetched; a gray frame is drawn. **Vendor icon sets** (AWS, Azure, GCP, Kubernetes composites, `img/lib` SVGs) are planned as optional, separately installable add-on shape libraries built on the library import mechanism (`.xml` mxlibrary, see the libraries package), not bundled in core; see ROADMAP.md (lowest priority).
- **Curved Text (`shape=curvedText`).** Not ported from draw.io: the interactive handles that drag `arcStartY`, `arcMidY` and `arcEndY` (edit them in the style), and `Graph.getPreferredSizeForCell`'s autosize for the shape (about 85 % of the straight text width). As upstream, the text is spread over the whole curve (`textLength`), so a long text on a short curve is squeezed and overlaps; on screen and in raster exports glyphs are placed one by one (no kerning or ligatures). The SVG export writes `<textPath>` (circular arcs as cubic segments instead of `A`); QtSvg ignores `textPath`, so such an SVG used as an image inside a diagram shows no text, and sketch mode leaves the text unsketched. The value is plain text: HTML markup is stripped, line breaks become spaces.
- **Sketch and comic.** `sketch=1` and `comic=1` are drawn by a clean-room hand-drawn renderer (`render/sketch_canvas.*`), not rough.js, so strokes and hachure lines look like draw.io's but are not the same shapes. Not ported: the `zigzag`, `zigzag-line` and `dots` fill styles (drawn as hachure), `shapeBackgroundColor` counting as a solid-fill background (only white does), and the sketch font substitution. Markers of sketched edges are hatched like any filled shape. The jiggle is seeded from the cell id, so it never varies between renders (draw.io's comic mode is random per render).
- **Fidelity against draw.io is measured, and not perfect.** [docs/FIDELITY.md](docs/FIDELITY.md) (`tools/fidelity/`) compares 123 files with draw.io Desktop 32.7.4: 98 are within 10 % on layout and 25 are above, with named causes (unshipped stencils and images, hatch fills, edge shapes, isometric edges, soft shadows, `<hr>` position and colour, list indentation, the routing of one file). Already fixed: text 1 to 5 px lower, `shape=rect` placeholders, trailing `<br>`, block margins, `wallU`, HTML tables in labels (`width`/`height` 100 %, padding, row backgrounds, vertical centring). The remaining classes and why they remain are in the document's "Current state". Text can still sit 1 px off draw.io's where Chrome and Qt pick different font files for the same family (Verdana, Courier). Only one page, scale 1, light theme and PNG are compared, and 123 files are a sample.
- **Zero-length edges are not drawn.** An edge whose route collapses to a single point (for example a self-loop with identical exit and entry constraints) produces the warning "edge has no usable terminals or points".
- **`--validate`, `--info` and `--convert` read XML only.** Only `--export` accepts a `.png`/`.svg`/`.pdf` with an embedded diagram (`format::readAnyFile`); the other commands report "unsupported root element <svg>".
- **Huge exports.** A diagram of about 10^8 units (for example `pathological/odd-numeric-formats.drawio`) fails PNG export with a "cannot allocate" error, and its PDF page size exceeds the 14400-unit limit most viewers accept. SVG export works.
- **`--embed` is ignored for JPEG.** No warning is printed.
- **PDF embedding.** The diagram is stored in `/Subject` as draw.io does; EmbeddedFile streams are read but not written. PDF text uses the system fonts.
- **Corpus undo/redo tests are slow.** `tst_commands_ops_pages_layers_corpus` takes about 34 s in the dev preset (a serial `ctest --preset dev` run, 24 cores; 90 to 130 s under asan) because every step serializes the document; `tst_ui_edit_corpus` takes about 31 s.
- **Labels depend on installed fonts.** PNG, JPEG and PDF output uses Qt's font matching (`Helvetica`, `Arial` and similar fall back to what the system has); SVG output keeps the font names.
- **Compressed bytes differ between zlib builds.** Re-compressed pages are deterministic per build, but zlib and zlib-ng can produce different valid streams (D-005).
- **XML declaration encoding is rewritten.** A file declared as `encoding="UTF-16"` (or any other encoding) is read correctly but saved as UTF-8 with `encoding="UTF-8"`.
- **Legacy payloads are upgraded.** Pages stored in the old non-URI-encoded or zlib-wrapped form are saved in the current draw.io encoding. The content is identical; the bytes are not.
- **Opaque pages cannot be forced inline.** `--uncompressed` leaves an undecodable page as it is.
- **Canvas paint: what is left.** The canvas paints from tiles rasterised on worker threads (ARCHITECTURE.md, "Canvas rendering", "Tiles on worker threads"); on the image-heavy synthetic document every hover, selection change, drag step, pan step, zoom step and edit takes 0.1 to 3 ms, and the GUI thread rasterises nothing in steady state (docs/BENCHMARKS.md). What remains: **soft frames during zoom**: while a zoom gesture runs, and for the 150 ms debounce after it (`TileScheduler::kSettleDelayMs`), the tiles of the bucket on screen are drawn scaled by up to 2x (up to 1.2x between two steps), so text is soft and then sharpens when the new bucket arrives (about 150 to 180 ms after the last frame in the benchmarks); a zoom step that finds the neighbouring bucket prefetched is sharp on its first frame; **a first paint, a jump to an area that was never shown and a pan faster than the one-tile ring still rasterise on the GUI thread** (`tilesRasterizedSync`; 0 per frame in Release pans, a few tiles per run in a Debug build); there is no coarse low-scale preview pass; **a label is laid out once per worker thread** that draws it (the text cache is per thread), so the first frames after an edit or a zoom do up to 8 layouts of the same label in the background; **`open` does the work the first paint did, for every cell**: recording a cell decodes its images and lays out its label, so off-screen images and labels are decoded and laid out at open (about 170 ms for the synthetic image-heavy document, 120 ms for 10k cells; making the decode lazy or moving it to workers is open); **memory** is high for image documents (peak about 600 MiB for the synthetic one: the tiles of the bucket on screen, the ring and the prefetch of the neighbouring buckets fill the 192 MiB tile budget (`QRAW_TILE_CACHE_MB`; other buckets' tiles are capped at a third), about 1.1 KB of recorded ops per cell, and the records keep their decoded images alive (`ImageData::cached`) beyond the image cache's budget) and a large style still exists twice (the attribute and its parsed token); **an edit that keeps the tree is cheap, a structural one is O(cells)** (see "Structural edits" below); **handlers without overlay bounds repaint the whole viewport**: only the move and rubber band gestures and the selection, edge, hover-arrow and fold handlers report `overlayBounds()` (`InteractionController`); resize, rotate, multi-resize, edge-end and waypoint drags, connect drags and table resizing return "unknown", which costs a whole-viewport update (a blit of the tiles, about 0.3 ms at 1600x1000) per mouse move and is counted in `viewportFullUpdates`. Off-thread text and fonts are verified on Linux only (ThreadSanitizer was not run; the asan preset and a stress test cover the rest); the threaded tests run in CI on macOS and Windows. Not done: admission control for regions that change every frame and idle warm-up of off-screen fonts and mips. An `image=` reference to a local file is looked at (size and time) on every record. An export after an image was shown decodes that image once more. The benchmark runs on the offscreen platform (no window-system flush is measured; a real session with a non-Fusion style may paint the widget frame, which is why `CanvasView` has none), the scope timers add about 10 % at 10,000 cells, and the PNG bytes of the synthetic document depend on the zlib version.
- **Live gesture preview: what is and is not in the active layer.** A move (Ctrl+drag included) and the resize and rotation of one vertex draw the changed cells live above the tiles (ARCHITECTURE.md, "Interaction snapshots and level of detail"). Still overlay outlines only: multi-selection resize and rotate, edge handle drags (ends, waypoints, segments), the connect gesture, table row and column resizing, and a Format panel slider (which edits per tick, not previews). While a gesture runs a lifted cell is drawn above everything in the tiles, so a cell that was under another one is shown over it until the release; the layer keeps the cells on screen after the release until the tiles of their new place are ready (at most 1 s, normally 5 to 50 ms), and a lifted cell can be doubled (once in the old tiles, once in the layer) for the time the tiles under it need to be rasterised again: 3 ms on the image-heavy synthetic document, tens of milliseconds for one cell on 10k cells in Fit Window. An edge that follows a moved or resized cell is re-routed without the jumps over other edges (`jumpStyle`), and the child cells of such an edge (labels that are cells) stay where they were until the release; the preview of an edge whose terminal is not lifted (a selected edge moved alone) is the rigid translation, the commit then disconnects it as before. A cell is lifted from the tiles when the pointer leaves the click tolerance, so the first move costs the tiles under it once (`dragLift`). A lifted set whose bitmap would exceed 16 Mpx is replayed live every frame (cells outside the viewport are skipped, so the cost follows what is visible).
- **Level of detail is deliberately modest.** At far zoom a cell below 1 px in both directions and a label whose font renders below 4 px are skipped on screen (never in export, print, thumbnails or hit testing). On the 10k-cell page at 15 % that is all the labels and no cell (a cell is 12 x 6 px), 11 % of a tile's replay time; the `drawPath` of thousands of small shapes is what a far-zoom tile costs and is not reduced (no simplified drawing for cells a few pixels wide, no greeked bars: not built, nothing measured calls for it). An outline or label of a skipped cell is not drawn, so a very large far-zoomed page shows fewer marks than at 100 %. LOD uses the nominal font size of the label's text block: a label with HTML spans of different sizes is judged by the block's size.
- **Text on the canvas is antialiased in grayscale.** Text is drawn into `QImage` tiles, where Qt does not use LCD (subpixel) antialiasing (it does for widget paint devices), so canvas text looks slightly lighter than it would with LCD antialiasing on a display that has it; exports, print and thumbnails are unchanged (golden tests untouched). Tiles are blitted at whole device pixels (next item for scaled displays).
- **Scaled displays (D-045): verified offscreen, not on a real desktop.** Verified by tests under `QT_SCALE_FACTOR` 1, 1.25, 1.5, 2 (and 3 for the tile tests) and `QT_FONT_DPI` 96, 120 and 144 on the offscreen platform (`ctest -L hidpi`, BUILDING.md "Scaled displays"): the composited canvas equals a direct render at the device ratio pixel for pixel, a scroll of one logical pixel at 125 % keeps it so, overlays are drawn from the tiles' whole device pixel, palette and welcome thumbnails and Copy as Image are rendered at the ratio, and a PNG export has the same pixels at every `QT_FONT_DPI`. **Not verified:** a Plasma session (fractional Wayland scaling with `wp-fractional-scale`, X11 with "Force font DPI" through `Xft.dpi`), a window dragged between two screens with different ratios (the thumbnail refresh on `QEvent::DevicePixelRatioChange` is tested with a synthetic event), toolbar and menu icons from a real icon theme (the offscreen platform has none: the buttons in the screenshots are text), and the label editor's text position at 125 % by eye (the tests pass; the editor is a widget with its own hinting and subpixel positioning).
- **A scroll that is not a whole number of device pixels repaints the viewport.** At 125 % a scroll of 1, 2, 3 or 5 logical pixels is 1.25, 2.5, 3.75 or 6.25 device pixels; the widget cannot scroll its old pixels by a fraction and paints the whole viewport instead (from cached tiles, nothing is rasterised; a scroll of 4 logical pixels, or of any multiple of 4, scrolls and paints only the strip). Measured on the offscreen platform in a Debug build; not timed on a real display.
- **Antialiased glyph pixels differ between the live canvas and a direct render at some ratios.** At a device ratio of 2.5 (a test composition, `QT_FONT_DPI=120` with `QT_SCALE_FACTOR=2`) one glyph of 49 pixels differs by up to 109 of 255 between the tiles and a render with the same transform: no shift (the best shift is (0, 0)), a different subpixel glyph position rounded in a tile's own coordinates. The tests do not run at 2.5.
- **Canvas frame removed.** `CanvasView` is a `QFrame::NoFrame` view: with a style that draws the frame expensively (Darkly: a blurred shadow, 6 to 20 ms per scroll step at 1600x1000) every scroll bar change repainted it. The canvas has no 1 px border any more; the docks around it have theirs.
- **Label metrics in `CellState::paintBounds` are estimates.** `CellState::paintBounds` still uses `geometry::estimateTextExtent` for the label (it was not wired to `render::labelTextRect` because that would move the export bounds and the golden files). The canvas does not depend on it: the recorded visual bounds of a cell (`CellRecord::visualBounds`, never smaller than `paintBounds`) contain the label at the size of its laid-out text (`labelMetrics`), checked by `tst_render_display_list`; the page area (`DiagramScene::pageArea`) and Fit Window still use `paintBounds`.
- **Interactive image scaling differs from exact scaling.** On screen an image is drawn from a box-filtered mip level (identical in every platform, no aliasing above 2x), in an export or print from the full-resolution image, as before; the two differ by a few levels per pixel. 16-bit PNGs are converted to 8 bits per channel on first use. SVG images on screen are drawn from a power-of-two raster of their destination size (an image larger than 64 MB of pixels is drawn as vectors), in exports as vectors.
- **Structural edits are O(cells) on the canvas.** An edit that only changes cells (move, style, value, terminals) patches the page view in place (`PageView::update`, D-037: 6 ms for one cell of 10,000 in Fit Window, 47 ms of 50,000, of which 35 ms is the tile replay of the touched tile (8,000 cells at 2 %), 3.4 ms the view update and the rest the snapshot's id index and the hit grid, which are rebuilt per edit), but adding, removing, re-parenting or reordering a cell, a page property, and a changed cell that has an attached edge which is not drawn, still build the view again and compare it with the old one (`PageView::build` 0.25 s at 50k cells; an `addConnection` drag release on 50k cells takes 0.31 s). Moving all 50k cells with a canvas takes about 1 s (re-recording every cell; the label layout cache is smaller than the 32,000 labels), duplicating them 2.2 s; undoing the duplicate 0.5 s. Group and ungroup of everything (50k cells, canvas alive): 0.74 s and 0.69 s, their undo 0.5 s (docs/BENCHMARKS.md). The snapper's guide search is still a scan of every vertex state (0.3 ms at 50k cells: a guide matches on a line, not a distance, so a spatial query cannot narrow it).
- **PNG export of 50k cells takes 3.4 s** at a long side of 4096 px (0.33 s for 1k cells at the same size, so the image size is a large part). The canvas work did not change it: export stays on the direct renderer (the figure varies between runs).
- **Qt ≥ 6.6 needed for `standalone` round trip.** With Qt 6.5, a `standalone` attribute in the XML declaration is dropped.
- **DTD internal subsets are expanded on load.** Entities declared in the internal subset are replaced by their text and `<!ATTLIST>` default attributes are added to elements (QXmlStreamReader behavior). The DOCTYPE is written back unchanged, so the result reloads identically, but the saved file contains the expanded text and attributes.
- **Unexpanded entities in attribute values.** A reference such as `&ext;` to an external DTD entity in an attribute cannot be told apart from the literal text `&ext;`; it is saved as `&amp;ext;` (a warning is reported when the file has a DOCTYPE).
- **Whitespace-only text between elements that contains a line break is treated as indentation** and regenerated on save, unless inside `xml:space="preserve"`.
- **Extreme numbers use exponent form.** `formatNumber` writes magnitudes below 1e-6 or from 1e21 as `1e+21`-style numbers.
- **CI coverage.** CI builds and runs the whole suite on Linux (Ubuntu 24.04, Qt 6.8), macOS (Qt 6.10) and Windows (MSVC 2022, Qt 6.8), plus the Linux packages. Linux is the platform used by hand; the macOS and Windows jobs, and the installer, ZIP and disk image they build, have had much less verification, and a text-measurement failure on one platform only is a font problem until shown otherwise (the Windows offscreen platform needs `QT_QPA_FONTDIR`, which the test environment sets; BUILDING.md, "CI"). Code paths that exist only on macOS and Windows (`.rc`, bundle icon, off-thread text) build there but are exercised only by the offscreen tests. CI has no ASan or long-fuzz job (cost; run them locally, see BUILDING.md), and GUI tests run offscreen only.
- **Hardening leftovers.** CI has no ASan/UBSan job and runs no long fuzz (the sanitizers were run by hand, BUILDING.md). The 120 s release fuzz run over the codec, compression, style and stencil targets predates the three HTML fixes and was not repeated (the HTML target was; an ASan fuzz run covered all five); the targets are blind to what the seeds do not reach (no corpus-guided coverage feedback, since libFuzzer is unavailable, D-028).
